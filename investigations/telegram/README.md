
# Telegram Android — Digital Forensic Investigation

## 1. Investigation Overview

This case study documents a forensic examination of the Telegram Android application conducted in a controlled laboratory environment.

The investigation focused on application behaviour, system logs, digital evidence collection, forensic artefacts, and changes observed during dynamic testing.

The objective was to develop practical Android forensic investigation skills and understand how application activity can be examined and documented.

## 2. Investigation Environment

| Component | Environment |
|---|---|
| Host Operating System | Windows |
| Target Application | Telegram Messenger |
| Platform | Android |
| Test Environment | Android Studio Emulator |
| Investigation Type | Controlled Forensic Examination |

## 3. Tools and Technologies

- Android Studio and Android Emulator
- Android Debug Bridge (ADB)
- Android Logcat
- Autopsy
- FTK Imager
- JADX
- SHA-256 Hashing Utilities

## 4. Investigation Methodology

The investigation followed a structured process:

### Phase 1 — Environment Preparation
- Prepared the Android emulator.
- Configured ADB connectivity.
- Installed and examined the target application.

### Phase 2 — Initial Evidence Collection
- Collected application and system logs.
- Recorded the initial application state.
- Generated SHA-256 hashes for evidence integrity verification.

### Phase 3 — Application Examination
- Examined the Android application using JADX.
- Used forensic tools to examine available evidence.
- Documented relevant technical observations.

### Phase 4 — Dynamic Testing
- Conducted controlled application testing.
- Observed application behaviour during test activities.
- Recorded changes and collected supporting evidence.

### Phase 5 — Forensic Documentation
- Organised investigation notes and screenshots.
- Documented the tools and procedures used.
- Prepared a technical investigation report.
